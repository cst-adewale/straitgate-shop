# Straitgate site

`public/` contains the public pages and assets. `server.js` serves these pages, maps `/` to `straitgate-home.html`, and checks the admin session before serving `private/straitgate-admin.html` at `/admin`.

`drafts/` contains older page designs and the authentication UI demo. Render does not publish this folder.

Keep `.env` in the project root. It is ignored by Git and outside Render's static publish folder.

The admin dashboard reads and writes products, inventory, and quotations through the protected `/api/admin/data` endpoint. Its overview uses those database records; the converter and calculator are local utilities. Set `DATABASE_URL` to the production Neon's pooled Postgres connection string in Render's Environment settings. Keep it secret. Until set, the dashboard shows a database configuration error rather than sample data. The server defaults to the production Neon Auth URL; set `NEON_AUTH_BASE_URL` only to use a different branch. Start with `node server.js` and open `http://localhost:3000/`. The Admin footer link opens the protected `/admin` route.

The admin footer links to protected `/admin/products` and `/admin/inventory` browsing pages. Both show their records as cards and can add an item to a quotation draft. Shop products bring their catalog price; inventory items start at ₦0 so the admin enters the selling price. The Inventory page includes both shop products and items entered directly in Inventory. Inventory-only products are never published to the shop.

`migrations/007_admin_upgrades.sql` was applied to the production Neon branch on 2026-11-08. Apply it to other branches before deploying this version there. It adds visitor analytics, material provenance, equipment and tool usage, and the private letterhead setting. The dashboard counts unique browser visitors over rolling 1, 7, and 30 day windows; signups count customer profiles. Top product is ranked by product page views. Visit tracking begins after deployment and does not backfill older traffic. Inventory now records who brought materials, acquisition time, who used equipment or tools, and return status. The quotation letterhead is uploaded in the admin page and stored privately in Postgres. Configure `REMOVEBG_API_KEY` on the server to enable the product image background removal toggle. Configure an OpenAI-compatible chat completions endpoint with `LLM_API_URL`, `LLM_MODEL`, and `LLM_API_KEY` to enable AI drafting; provider pricing and free-tier availability depend on the provider. Keep all keys in server environment settings, never in browser code.

`migrations/008_confirmed_payment_charts.sql` was applied to the production Neon branch on 2026-11-08. The dashboard's Revenue card shows confirmed payment totals for the selected daily, weekly, or monthly range from `confirmed_payments`. The unique reference constraint prevents duplicate recording. The dashboard has no payment entry control, and there is no automatic payment-provider verification yet; a quotation status does not create revenue.

The dashboard accepts up to five PNG or JPG files per product, converts them to JPEG, and uploads them to a private Cloudflare R2 bucket. Choose the main image before saving, or change it later from the dashboard. Create a bucket and bucket-scoped Object Read & Write R2 API token in Cloudflare, then set `R2_ACCOUNT_ID`, `R2_BUCKET`, `R2_ACCESS_KEY_ID`, and `R2_SECRET_ACCESS_KEY` in Render's Environment settings. For an EU, US, or FedRAMP jurisdiction bucket, also set `R2_ENDPOINT` to its jurisdiction-specific S3 endpoint. Never put these secrets in `public/` or commit them. The app stores image keys in Neon and serves images for published products through `/api/product-image/:id` and `/api/product-image/:id/:index`; the bucket does not need public access. Image uploads require all R2 settings. A product without an image can still be saved.

`render.yaml` defines a Node web service with the production Neon Auth URL. Render does not need `ADMIN_EMAIL`, `ADMIN_PASSWORD`, or `SESSION_SECRET`. If the site was already deployed as a Render Static Site, create a new Blueprint/web service from this configuration and switch the domain to it. A Static Site cannot enforce server-side admin access.

## Neon status

The existing `straitgate` Neon project has Managed Auth and the Data API enabled on its production branch. `migrations/001_straitgate_core.sql` has been applied to production and to a separate `dev` branch. It creates `products`, `inventory_items`, and `quotes` with row-level security. `migrations/002_admin_data.sql` adds product image data and quotation validity dates; it has been applied to production and dev. `migrations/003_r2_images.sql` adds the R2 object key. `migrations/004_product_gallery.sql` adds up to five image keys and a main-image index; it has been applied to production. Apply it to the dev branch before using the gallery there. The first production Auth admin account is `gospel.adewale7@gmail.com`.

`neon.ts` declares the desired Auth and Data API configuration. Do not place Neon credentials in `public/` or commit them to source control. The Data API URL is branch-specific; use the production URL when configuring production.

`server.js` sends sign-in and session checks to Neon Auth and allows access to `/admin` only when the Neon user has role `admin`. The admin login modal's Forgot password action requests a Neon reset email; the email links to `/straitgate-reset-password.html` for choosing a new password. Set `PUBLIC_ORIGIN` to the actual deployed site origin and add that origin to the production branch's Neon Auth trusted domains. The public catalog and product details now read published products from `/api/products`; an admin-added product is published immediately. The shop will be empty until real products are added. No tax is added to quotations until a business tax policy is configured. Verify the full flow on the deployed app. Neon currently uses shared SMTP; configure custom SMTP for production email delivery.

The admin header has a backend-health pill. Its panel shows live request latency, Neon query latency, server uptime, and a chart of checks made in the current tab. While the admin page remains open, it sends a random-signal ping every 14 minutes. Browser timers may be delayed and stop when the tab closes; this is not an always-on keepalive or a replacement for a paid Render instance.

## Customer accounts

The `/straitgate-account.html` page requires email, username, phone, and a password of at least 12 characters for registration. Neon Managed Auth stores the user and password hash in `neon_auth`; `public.customer_profiles` stores a unique lowercase username and phone, linked by Neon user ID. Passwords are never stored in the profile table. The production `migrations/005_customer_profiles.sql` migration has been applied. Apply it to any other Neon branch before using customer registration there. The production Auth configuration currently permits email/password signup but does not require email verification; enable verification and configure custom SMTP before relying on customer identity for orders or payments. Test a real signup and login after deploying.

## Encrypted Cloudflare database backup

`.github/workflows/database-backup.yml` is a daily 03:17 UTC GitHub Actions job, disabled until the repository variable `BACKUP_ENABLED` is set to `true`. It uses PostgreSQL 18 `pg_dump` with a **direct, non-pooled** Neon connection, encrypts the full dump using AES-256-GCM, and uploads it to a separate private R2 bucket. It does not use the product-image bucket or its token. Create `straitgate-db-backups` as a private bucket and create a separate bucket-scoped Object Read & Write R2 token. Add these GitHub Actions repository secrets: `DATABASE_URL_UNPOOLED`, `R2_BACKUP_ACCOUNT_ID`, `R2_BACKUP_BUCKET`, `R2_BACKUP_ACCESS_KEY_ID`, `R2_BACKUP_SECRET_ACCESS_KEY`, and `BACKUP_ENCRYPTION_KEY` (base64 of 32 random bytes). If the bucket has a jurisdiction-specific endpoint, also set `R2_BACKUP_ENDPOINT`. Keep the encryption key in a separate secure password manager; losing it makes backups unrecoverable. After configuring secrets, set `BACKUP_ENABLED=true` under repository Actions variables and run the workflow manually once. Verify an object appears in the bucket and test decryption with `BACKUP_ENCRYPTION_KEY` set: `node scripts/decrypt-backup.js encrypted.dump.sge restored.dump`. Restore only to an isolated Neon branch after reviewing the dump. Configure a private-bucket lifecycle/retention rule so daily dumps do not accumulate indefinitely. The workflow has not been activated or live-tested yet; GitHub scheduled runs can be delayed, so monitor failures and periodically test restores.
